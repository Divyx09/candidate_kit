# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Timezone mismatch in shift start calculation: `punch_in.replace(hour=h, minute=m)` modifies the timestamp in its input timezone. If `punch_in` is in UTC, 09:30 IST shift is evaluated as 09:30 UTC (04:00 UTC shift treated as 09:30 UTC), yielding negative or incorrect elapsed time. | Punch-in at 09:35 IST (04:05 UTC) on 09:30 shift: calculates 04:05 UTC minus 09:30 UTC (-325 min), returning 0 late minutes. | Explicitly convert `punch_in` to IST timezone before building shift start datetime in IST. |
| 2 | `compute_late_minutes` (lines 33–38) | Overnight shift ignorance (R1): For overnight shifts (`shift_end <= shift_start`, e.g., 22:00–06:00), punch-ins before `shift_end` (e.g., 05:30 IST) belong to the shift that started on the previous day. Starter sets shift start on the current calendar day at 22:00 (in the future). | Punch-in at 05:30 IST for 22:00–06:00 shift: start is set to 22:00 same day (16.5 hours in future), returning 0 late minutes. | Apply R1 overnight rule: if `shift_end <= shift_start` and `punch_in_ist.time() < shift_end`, shift start date is previous day. |
| 3 | `compute_late_minutes` (lines 36–37) | Grace period threshold truncation bug (R2): Computes `minutes = int(total_seconds / 60)` before checking `minutes > 10`. For 09:40:01, `int(601 / 60) = 10`. The check `10 > 10` is False, incorrectly returning 0. | Punch-in at 09:40:01 on 09:30 shift: rule specifies 10 minutes late, starter returns 0. | Check strict threshold `total_seconds > 600`. If true, return `floor(total_seconds / 60)`. |
| 4 | `compute_work_hours` (lines 40–41) | Banker's rounding instead of round-half-up (R4): Python's built-in `round()` performs round-half-to-even. | Worked duration of 2.675 hours (9630 seconds): `round(2.675, 2)` gives `2.67`, whereas R4 requires `2.68`. | Used Python `decimal.Decimal` with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` (lines 44–47) | Missing 30-minute qualification threshold (R3): Returns minutes directly without verifying `minutes >= 30`. | Punch-out at 18:35 on 18:30 shift: returns 5 overtime minutes; rule requires 0 because overtime under 30 min is ignored. | Return `minutes` only when `minutes >= 30`, otherwise return 0. |
| 6 | `compute_overtime` (lines 44–47) | Overnight shift calendar date bug (R1): Sets `shift_end` on `date_str` unconditionally. For overnight shifts (e.g. 22:00–06:00), `shift_end` falls on `date_str + 1 day`. | Overnight shift on 2026-07-06 with punch-out at 06:40 on 2026-07-07: calculates 06:40 on 7th minus 06:00 on 6th, reporting 1480 minutes of overtime. | If `shift_end <= shift_start`, set `shift_end` date to `attendance_date + 1 day`. |
| 7 | Whole seconds truncation (Global/R1) | R1 requires instants to be truncated to whole seconds before any calculation, and the truncated value must be stored and returned. Starter did not truncate. | Passing `09:40:00.900` treated as fractional seconds instead of `09:40:00`. | Added `truncate_to_whole_seconds()` (`ms // 1000 * 1000`), persisting and returning truncated values. |
| 8 | `health` (lines 72–74) | Readiness probe does not ping MongoDB: Returns `{"status": "ok"}` unconditionally even if MongoDB is down. | Stop MongoDB: `GET /health` returns 200 instead of required 503. | Wrapped `client.admin.command("ping")` in try/except; raises `HTTPException(503)` on failure. |
| 9 | `create_employee` (lines 79–84) | Check-then-insert race condition: `find_one` followed by `insert_one`. Concurrent requests with the same `emp_code` both pass the check and trigger unhandled 500 `DuplicateKeyError`. | Send two concurrent `POST /employees` with identical `emp_code`: one returns 201, the other crashes with 500. | Enforced unique index on `emp_code` and caught `DuplicateKeyError` to raise `HTTPException(409)`. |
| 10 | `EmployeeIn` model (lines 53–60) | Missing input validations: Lacks regex patterns for `emp_code` (`^EMP\d{4,6}$`), email format, length bounds, and validation that `shift_start != shift_end`. | POST with `emp_code: "foo"` or `shift_start: "09:00", shift_end: "09:00"` accepts invalid data instead of returning 422. | Added strict Pydantic `Field` patterns, constraints, and model validator ensuring `shift_start != shift_end`. |
| 11 | `create_employee` / `list_employees` (lines 82, 95) | Contract violation on `created_at`: Stored as naive local datetime and returned as datetime object (serialized as ISO-8601 string) instead of integer epoch milliseconds. | `created_at` in JSON response is `"2026-01-05T04:30:00"` instead of integer `1767587400000`. | Store BSON UTC datetime; convert to integer epoch milliseconds in all response formatters. |
| 12 | `list_employees` (line 93) | Off-by-one pagination calculation: `skip = page * page_size`. For `page=1, page_size=20`, skips 20 items, returning page 2. | `GET /employees?page=1&page_size=20` returns records 21–40 instead of 1–20. | Corrected formula to `skip = (page - 1) * page_size`. |
| 13 | `list_employees` (line 94) | Filtered total count ignored: `total = db.employees.count_documents({})` counts the entire collection instead of filtered query. | Filter by department with 2 matching employees: `total` returns 100 instead of 2. | Changed to `total = db.employees.count_documents(q)`. |
| 14 | `list_employees` (line 95) | Missing sorting: Contract specifies sorting by `emp_code` ascending; starter used non-deterministic natural order. | Employees returned in arbitrary insertion order. | Added `.sort("emp_code", ASCENDING)`. |
| 15 | `punch_in` (lines 101, 113) | Crash with 500 when employee is not found: `emp = db.employees.find_one(...)` returns `None`, and `emp["shift_start"]` raises `TypeError`. | Punch in with unknown `emp_code`: returns 500 instead of 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 16 | `punch_in` (lines 102–103) | Attendance date calculation uses machine local time and ignores overnight shift rule (R1). | Overnight shift punch-in at 05:30 IST on 2026-07-07 assigned to 2026-07-07 instead of shift date 2026-07-06. | Implemented `get_attendance_date()` converting UTC instant to IST and applying R1 overnight logic. |
| 17 | `punch_in` (lines 104–105) | Check-then-insert race condition on `(emp_code, date)`: Concurrent punch-ins can both pass `find_one` and create duplicate logs or trigger 500. | Send two concurrent punch-in requests: both pass check, causing duplicate records or 500 error. | Enforced unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return 409. |
| 18 | `punch_in` (lines 119–121) | Schema contract violations: Injected internal `"id"` field into response; returned datetime object for `punch_in` instead of epoch milliseconds. | Response validation against `AttendanceRecord` fails due to unexpected `id` and non-integer `punch_in`. | Strip internal MongoDB IDs and convert all datetime fields to integer epoch milliseconds. |
| 19 | `list_attendance` (lines 144–146) | In-memory loading and sorting of entire collection: `list(db.attendance_logs.find(q))` loads all records into Python memory before sorting. | Querying with 100k records causes severe memory spikes, slow responses, or crashes. | Push sorting and pagination directly into MongoDB: `.sort(...).skip(...).limit(...)`. |
| 20 | `list_attendance` (line 145) | Missing secondary sort key: Starter only sorted by `date` descending, omitting `emp_code` ascending tie-breaker. | Records on the same date appear in non-deterministic order. | Added compound sort: `[("date", DESCENDING), ("emp_code", ASCENDING)]`. |
| 21 | `list_attendance` (line 136) | Missing date range validation: If `date_from > date_to`, contract requires 422. Starter allowed it and returned an empty list. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returned 200 instead of 422. | Added validation: `if date_from > date_to: raise HTTPException(422)`. |
| 22 | `list_attendance` (lines 148–150) | Missing legacy document handling: Older seeded documents omit `half_day` or `history`. Starter did not provide defaults. | Legacy documents fail response schema validation because required fields `half_day` and `history` are missing. | Formatted records to default `half_day: False` and `history: []` when absent. |
| 23 | Startup index creation (lines 22–28) | Missing startup index initialization: App did not create indexes at startup idempotently as required. | Grader queries trigger collection scans (`COLLSCAN`), failing speed/explain checks. | Added `@app.on_event("startup")` creating all required unique and compound indexes. |
| 24 | PyMongo client initialization (line 22) | Missing `tz_aware=True`: PyMongo defaults to naive UTC datetimes, causing `TypeError` when combined with timezone-aware IST datetimes. | Datetime arithmetic throws `TypeError: can't compare offset-naive and offset-aware datetimes`. | Configured `MongoClient(..., tz_aware=True)`. |

---

### What was examined and confirmed NOT to be a defect:
1. **`load_dotenv()` at top of file**: Confirmed safe because `load_dotenv()` does not override existing system environment variables by default (`override=False`). Injected `MONGO_URI` and `MONGO_DB` from the grader take precedence.
2. **Natural key addressing `(emp_code, date)`**: Confirmed that attendance records have no public ID and must be addressed purely by employee code and attendance date.
3. **Stored derived fields as authoritative**: Confirmed that `work_hours`, `late_minutes`, `overtime_minutes`, and `half_day` should be read directly by analytics without recomputing from punch times.
